Step 2

Give it a Mac that stays awake.

This is the one real requirement, and it's worth getting right. Your assistant is only alive while its computer is. A sleeping Mac is an assistant that isn't there.

You don't need a new machine or a spare one. You need one machine that's plugged in and not napping. Find yourself below:

🖥️

Desktop Mac

Mac mini, Studio, iMac. Easiest case by far — one setting and you're done. This is what most people end up with eventually.

💻

Laptop, lid open

Plugged in, lid up, sleep set to never. Totally fine, and how nearly everyone starts. It just has to live somewhere it can stay open.

🔌

Laptop, lid closed

Closed-lid — clamshell — only works with power and an external display and a keyboard or mouse connected. Unplug the monitor and it sleeps.

You don't have to configure this yourself. The prompt in step 3 checks which kind of Mac you're on, sets the sleep behavior to match, and shows you how to undo it. This section is just so you know what it's doing and why.

If it has to sleep at night, that's still fine. You get a fully working assistant that's simply offline while you are. The only thing you lose is work happening overnight — briefings, scans, anything scheduled. That's the honest reason to add a cheap always-on Mac later: because you got hooked, not because you're doing it wrong now.

Two things to know. A laptop working hard with the lid shut runs hotter, so give it air. And on Windows this all works too — power settings are under Settings → System → Power, and the prompt handles it.

Step 3

Paste this. Watch it build itself.

Open the desktop app from step 1, let it run things on your computer (that's the next section), then paste this in and send. It installs everything, keeps your Mac awake, connects your phone, and checks its own work before it tells you it's done.

The whole setup, in one paste
I want to set up OpenClaw on this computer so I have my own always-on AI
assistant that I can text from my phone. Please do the entire setup for me.

Assume I am not a developer. Do not ask me to make technical decisions, and
explain each step in plain language as you go. Do the work yourself rather
than handing me instructions to follow.

1. Read the official guide at https://docs.openclaw.ai/start/getting-started
   first and follow that, rather than anything you remember. It changes.

2. Install it by running:
   curl -fsSL https://openclaw.ai/install.sh | bash
   That script brings its own Node and anything else it needs. Do not install
   Homebrew, Node, Git, a code editor or a terminal app separately.

3. The installer opens a setup wizard on its own. Walk me through it. When it
   asks about the AI provider, reuse my existing Claude or ChatGPT
   SUBSCRIPTION login. Do NOT set up a pay-per-use API key, and do not create
   any billing account.

4. Make it run in the background and survive a restart:
   openclaw gateway install

5. Keep this machine awake, because the assistant only runs while it is.
   Work out what kind of computer this is and set it up to match:
   - A desktop Mac: set the computer to never sleep while on power.
   - A laptop I keep open: never sleep while plugged in, and tell me to leave
     it plugged in with the lid up.
   - A laptop with an external display: tell me it can run lid-closed, but
     only while plugged in with the display and a keyboard or mouse attached.
   Tell me which case I am, show me the setting you changed, and tell me how
   to undo it.

6. Set up Telegram so I can text it from my phone: help me create a bot with
   @BotFather, get the token, and lock it down so only my own account can
   message it. Tell me exactly what to tap on my phone.

7. Prove it works. Run: openclaw gateway status
   Then have me send a real Telegram message and confirm I get a reply back.
   Do not tell me it is done until you have seen it reply. If something
   breaks, run: openclaw triage

8. Ask me a handful of questions about who I am and what I do, and write the
   answers into its memory files so it knows me from day one.

Rules: stop and ask me before anything that costs money, sends a message to
another person, or deletes files. At the end, give me a short list of what
you set up, where it lives, and three things I should try first.
It'll ask permission before running things on your machine. That's normal, and it's the point — but read what it's about to do before you approve it. Never approve something that deletes files or spends money if you don't understand it.

The one setting you flip yourself.

Step 3 only works if the desktop app is allowed to run things on your computer. Both apps ship locked down, on purpose.

ChatGPT: the setup runs in Codex, inside the ChatGPT desktop app. Point it at a folder on your computer and allow it to run commands there.

Claude: same idea — Claude Code, inside the Claude desktop app, pointed at a folder on your machine.

Approve as you go, at least at first. Letting it run without asking is faster, and it's where most people end up — but only after watching it work for a while. There's no undo on a command that already ran.

These menus move around every few weeks as the apps update, so no guide stays right for long. If you can't find it, ask the app itself: "how do I let you run commands on my computer?" It knows its own settings better than this page can.

What we left out, on purpose.

Every other guide hands you a download list. Here's why this one doesn't.

Node.js, Homebrew, Git

The installer puts these in for you. If a guide tells you to download them first, that guide is out of date.

A fancy terminal — iTerm2, Warp, Ghostty

The terminal already on your Mac is fine, and doing it this way you barely open it. These are for people who live in a terminal all day. You won't.

VS Code, or any code editor

You're not the one writing code — your assistant is, and it edits its own files directly. Install an editor only if you personally want to sit and read them.

A cloud server or VPS

Tempting, and it's a downgrade. A Linux box in a datacenter can't touch your messages, contacts, calendar, mail, photos or logged-in browser — which is most of what makes this feel like magic.

A second computer

Genuinely nice once you're hooked and want things running at 4am. Completely unnecessary to start, and you'll know when you want one.

API keys and credits

Your normal Claude or ChatGPT subscription is enough. Setting up billing at an API console is how people accidentally spend real money.

Once it's alive.

Don't open with a big project. Open by proving to yourself it's real.

“What's on my calendar tomorrow?”
“Summarize this for me: [paste a link]”
“Watch this page and text me if the price drops.”
“Go through my inbox and tell me what actually needs me.”

Then let it get to know you. This gets dramatically better once it has real context on who you are and how you work — and unlike a chat window, it writes that down and keeps it.

Later, when you want more.

Don't set any of this up now. When you hit the moment you want one, just ask your assistant to add it. It can do its own installs.

A password manager

Somewhere safe for it to keep logins, instead of you pasting passwords into a chat window.

A private network

Reach the home machine from anywhere, without opening it up to the internet.

Version control

A free undo button for its memory and notes. You'll want this the first time it deletes something you liked.

Discord

Separate rooms — alerts here, logs there, one per project — for when a single Telegram thread stops being enough.

A voice

So it sends voice notes instead of walls of text. Purely for fun. A lot of fun.

Web hosting

So it can build you dashboards and put them online. This page is an example of that.
